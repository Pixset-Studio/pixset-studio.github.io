# 🌐 Site — сайт Byte Blaster

Статический сайт для GitHub Pages: главная, вики и страница 404.
Адрес: **https://pixset-studio.github.io/byte-blaster/**

---

## Что где лежит

```
Site/
├── index.html          главная (кнопки «играть», «купить», RuStore)
├── 404.html            страница ошибки
├── .nojekyll           отключает Jekyll (иначе он выкинет папки на «_»)
├── assets/
│   ├── site.css        стили всех страниц
│   ├── site.js         язык, плавные переходы, поиск по вики
│   ├── logo.png        иконка игры 192×192 (шапка)
│   ├── logo-512.png    иконка игры 512×512 (главная, OG-превью)
│   └── favicon…        иконки вкладки
├── wiki/
│   └── index.html      вики: механики, миры, боссы, сюжет, FAQ
├── download/
│   └── index.html      где скачать: браузер, RuStore, Windows + требования
├── updates/
│   └── index.html      история версий
└── game/              веб-сборка игры
```

## Админка и статистика

Страница `/admin/` показывает посещаемость и число игроков. Сайт статический и
сам считать не может, поэтому счётчиками занимается **relay-сервер
мультиплеера** — он уже развёрнут и доступен из браузера.

### Что нужно сделать один раз

1. **Передеплоить сервер.** В `Byte Blaster Server/` появились `stats.js` и
   правки в `server.js`. Залейте их в репозиторий сервера — Railway пересоберёт
   сам.
2. **Прописать адрес сервера** в `assets/config.js`:
   ```js
   window.BB_STATS_API = 'https://ВАШ-ДОМЕН.up.railway.app';
   ```
   Домен виден в Railway: Settings → Networking → Public Networking. Нужен
   именно `https://`, а не `wss://` — это тот же хост.
3. **Задать пароль через переменные окружения** Railway (рекомендуется):
   `ADMIN_USER` и `ADMIN_PASS`. Если их не задать, сервер использует значения по
   умолчанию, вшитые в `stats.js`.

### Что считается

| Показатель | Откуда берётся |
|---|---|
| Визиты и посетители | каждая страница сайта шлёт `POST /api/hit` |
| Запуски игры | `assets/telemetry.js` в игре, один раз за сессию |
| Игроки онлайн, комнаты | живое состояние relay-сервера |
| Созданные комнаты, матчи | события `create_room` и `start_game` |
| Разбивка по страницам, языкам, платформам, версии | из тех же событий |

Периоды: сутки, неделя, месяц, год, всё время. Плюс график за 30 дней.

### Ограничения, о которых честно

- **Файловая система Railway эфемерна**: при редеплое история обнулится, если не
  подключить том и не указать его в `STATS_DIR`.
- **Уникальные посетители** считаются по обезличенному отпечатку (IP + браузер),
  который живёт только текущий день. За сутки цифра точная; за неделю и больше
  один человек, заходивший в разные дни, посчитается несколько раз.
- **Токен сессии** живёт 8 часов и хранится в памяти: перезапуск сервера
  разлогинивает.
- Игра сообщает только факт запуска, редакцию, платформу и язык интерфейса.
  Ничего личного, никакого прогресса.

## Анимации

Вся анимация живёт в блоке `MOTION` в `assets/site.css` и в разделе `Motion`
внутри `assets/site.js`. **В разметке страниц её нет** — появление при прокрутке
навешивается скриптом, поэтому новый блок на любой странице анимируется сам.

Правила, которых стоит держаться при доработке:

- Анимировать только `transform`, `opacity`, `filter` и `background-position` —
  их браузер отдаёт видеокарте без пересчёта раскладки. Никаких `width`,
  `height`, `top`, `left`: это вызывает reflow и роняет плавность на телефоне.
- **Не навешивать появление на содержимое `<details>`.** Пока спойлер закрыт, у
  него нет размеров, наблюдатель не срабатывает — и текст остался бы прозрачным
  навсегда. Скрипт такие элементы пропускает, плюс через 4 секунды показывает
  всё, что почему-то осталось скрытым.
- Любая новая анимация обязана отключаться в блоке `prefers-reduced-motion` в
  конце файла стилей.

## Два языка

Сайт двуязычный (RU / EN) **без дублирования страниц**: оба перевода лежат в
одной разметке, а показывается нужный.

```html
<p data-l="ru">Русский текст</p>
<p data-l="en">English text</p>
```

- Активный язык — атрибут `data-site-lang` на `<html>`; CSS прячет неактивный.
- Язык выбирается так: сохранённый выбор → язык браузера → русский. Для
  кириллических локалей (ru, uk, be, kk, ky, uz, tg, tk, az, hy) берётся
  русский, для остальных английский.
- Выбор запоминается в `localStorage` под ключом `bbSiteLang`.
- Значение проставляется **инлайн-скриптом в `<head>`**, до первой отрисовки —
  иначе страница на мгновение мигала бы не тем языком.
- `<title>` и описание нельзя спрятать через CSS, поэтому их варианты лежат в
  `data-title-ru` / `data-title-en` / `data-desc-*` на теге `<html>`.

**Добавляя текст, пишите сразу обе версии** — иначе при переключении на другой
язык блок просто исчезнет.

## Какие папки создать в репозитории GitHub

Репозиторий должен называться **`byte-blaster`** (именно так — от этого зависит
адрес `…github.io/byte-blaster/`), владелец — **`pixset-studio`**.

**Содержимое папки `Site/` кладётся в КОРЕНЬ репозитория**, не внутрь папки
`Site`. То есть в репозитории должно получиться так:

```
byte-blaster/               ← корень репозитория
├── index.html
├── 404.html
├── .nojekyll
├── assets/
│   ├── site.css
│   ├── site.js
│   ├── favicon.ico
│   ├── favicon-32x32.png
│   └── apple-touch-icon.png
├── wiki/
│   └── index.html
└── game/
    ├── index.html      ← файлы веб-сборки игры
    └── assets/ …
```

Именно такая раскладка даёт адреса, которые стоят в кнопках:

| Кнопка | Адрес | Что его создаёт |
|---|---|---|
| Главная | `…/byte-blaster/` | `index.html` в корне |
| Вики | `…/byte-blaster/wiki/` | папка `wiki/` с `index.html` |
| Скачать | `…/byte-blaster/download/` | папка `download/` с `index.html` |
| Обновления | `…/byte-blaster/updates/` | папка `updates/` с `index.html` |
| О проекте | `…/byte-blaster/about/` | папка `about/` с `index.html` |
| Админка | `…/byte-blaster/admin/` | папка `admin/` с `index.html` |
| ▶ Играть | `…/byte-blaster/game` | папка `game/` с `index.html` |
| 404 | любой неверный адрес | `404.html` в корне |

Внешние ссылки, которые стоят на сайте: RuStore
(`rustore.ru/catalog/app/com.pixsetstudio.byteblaster`) и GitHub Releases
(`github.com/pixset-studio/byte-blaster/releases`) на странице «Скачать».
**Если релизов .exe там нет — либо выложите сборку, либо уберите карточку
Windows**, чтобы кнопка не вела в пустоту.

> Адрес без слэша на конце (`/game`) работает: GitHub Pages сам добавит
> слэш и отдаст `index.html` из этой папки.

## Как собрать игру для сайта

> Сейчас в `game/` **уже лежит рабочая сборка** версии 1.0.2. Этот раздел
> нужен, когда выйдет обновление игры и сборку надо заменить.

Веб-сборка делается из папки `Game/`:

```bash
cd Game
npm run build:html
```

Результат появится в `Game/dist/Byte Blaster (HTML)/` — **содержимое этой папки**
копируется в `game/`.

Отдельной демоверсии больше нет: играется полная игра, а платные части
открывает лицензия аккаунта.

## SDK аккаунтов

Страницы «Аккаунт», «Купить», «Скачать» и админка работают через общий модуль
студии `assets/pixset-auth.js`. Здесь лежит **копия**, а исходник — в
`Pixset Studio Site/assets/`.

Раньше страницы грузили его прямо из корня домена, то есть из соседнего
репозитория. Стоило поправить SDK и не перезалить сайт студии — админка падала
с `does not provide an export named …`. Своя копия убирает эту связь, но её
надо обновлять после правок SDK:

```bash
node sync-sdk.js
```

Скрипт заодно метит модуль версией: подставляет короткий хэш в `SDK_VERSION`
и в адреса импорта (`pixset-auth.js?v=…`) на обоих сайтах. Без метки браузер
держит старую копию в кэше, и страница молча работает на вчерашнем коде —
именно так загрузка сборок падала без единой ошибки в консоли. Текущая версия
видна в админке рядом с ником: если там старый хэш, страница взяла модуль из
кэша.

### Аватар в профиле

Картинка хранится прямо в `profiles.avatar_url` как `data:`-URL, а не в
Storage: отдельный бакет потребовал бы своей политики доступа, а аватар после
сжатия весит килобайт пятнадцать. Ужимает файл браузер — `avatarFromFile()`
в SDK обрезает картинку по центру в квадрат, сводит к 160×160 и подбирает
качество JPEG, пока не уложится в 64 КБ (телефонное фото на 4 МБ превращается
в ~15 КБ). Запись разрешает та же политика «own profile update», что и смену
ника, — ничего настраивать в Supabase не нужно.

Страница показывает `avatar_url`, только если он выглядит как картинка
(`data:image/…;base64,`): в колонку может попасть что угодно, а в `src` должна
уходить именно картинка, не ссылка на чужой хост.

### Друзья и публичный профиль

Живут на сайте студии (`/account` — список и заявки, `/u/?n=ник` — чужая
карточка с прогрессом в играх). Аккаунт общий, поэтому из игры видно тот же
список: в Byte Blaster это вкладка «Друзья» в профиле.

**Требуется один раз применить** `Pixset Studio Site/supabase/migrations/0002_friends.sql`
в Supabase → SQL Editor. Пока миграция не применена, страницы честно пишут, что
возможность не включена в базе, — ничего не ломается.

Прогресс в чужой карточке берётся из таблицы `game_stats`: игра публикует туда
короткую сводку после каждого сохранения в аккаунт. Само сохранение остаётся
приватным в `cloud_saves` — в витрину уходят только числа.

### Суммы в покупках

`orders.amount` хранится в **копейках и центах** — так его пишет сервер и так
же делит функция оплаты. Список покупок на странице аккаунта делить забывал, и
$1.50 показывался как «$150.00». Если добавляете вывод суммы — делите на 100.

## Что важно знать

- **Пути в HTML абсолютные** (`/byte-blaster/…`). Если репозиторий назвать
  иначе, нужно заменить этот префикс во всех файлах — иначе ссылки, стили и
  иконки не найдутся.
- **`.nojekyll` обязателен.** Без него GitHub Pages пропускает через Jekyll,
  который игнорирует файлы и папки, начинающиеся с подчёркивания — а в
  локализации игры такие файлы есть.
- **Игра и сайт делят `localStorage`**, потому что живут на одном домене:
  оттуда веб-версия берёт вход в аккаунт, туда же кладёт прогресс. Бесплатная
  часть и полная версия — это одна и та же сборка, разницу решает лицензия.
- **Служебные файлы удалены из сборок.** Веб-сборка тянет за собой отчёты
  аудита локализации (`_suspect_*.json`, `_cutscenes_en.json`, `_pre_en.json` —
  78 файлов), которые игре не нужны. Они убраны; если пересоберёте — удалите
  снова:
  ```bash
  find game -name "_*.json" -delete
  ```

- **Локально сайт смотреть так.** Пути абсолютные (`/byte-blaster/…`), поэтому
  открывать `index.html` двойным щелчком бесполезно — нужна структура, где
  папка сайта называется `byte-blaster`:
  ```bash
  mkdir preview && cd preview
  ln -s "../Site" byte-blaster      # Windows: mklink /J byte-blaster ..\Site
  python -m http.server 8080
  ```
  затем открыть `http://localhost:8080/byte-blaster/`.
